# Security policy

## Supported versions

Security fixes go into the latest release only. Update both the extension in
your deck (`quarto add seandavi/quarto-revealjs-live-questions`) and your server when a fix
is released.

| Version | Supported |
|---|---|
| 1.x (latest) | yes |
| older | no |

## Reporting a vulnerability

Please report vulnerabilities privately through GitHub's private
vulnerability reporting: open the repository's **Security** tab and choose
**Report a vulnerability**
(<https://github.com/seandavi/quarto-revealjs-live-questions/security/advisories/new>).
Do not open a public issue for a security problem.

Include what you found, how to reproduce it, which runtime it affects
(Cloudflare, Docker/Node, the deck plugin or the phone page) and what an
attacker could do with it. You should get a first reply within a week. Once
a fix is ready, it will be released with a GitHub security advisory that
credits you, unless you prefer not to be named.

## Scope

In scope, for example:

- Gaining presenter control (opening, closing, revealing, resetting or
  hiding) without the presenter key, or learning the key from the deck, the
  phone page or the server's responses.
- Reading another session's data, or the export, without the key.
- Script injection through question text, options or audience answers, on
  the slide or on phones.
- Crashing or wedging a server or a session with crafted messages, beyond
  what the documented rate limits allow.
- Problems in how the Cloudflare or Docker deployment is configured by this
  repository (headers, routes, container user).

Known and accepted limits, not treated as vulnerabilities (see "Privacy and
limits" in the README and "Security model" in SPEC.md):

- Voter ids are generated by the client, so one person can vote more than
  once using private windows, other browsers or a script.
- Correct quiz answers are present in the rendered deck HTML.
- There is one presenter key per server, shared by all sessions on it.
  Anyone who has the key can control every session on that server.
- Anyone who knows a session name can join it, see the live question and
  vote. Session names are not secrets.
- Word-cloud answers are not filtered for offensive content.

A leaked presenter key is fixed by setting a new one
(`bunx wrangler secret put PRESENTER_KEY`, or a new `PRESENTER_KEY` in
`.env` and a container restart) and re-opening your deck with
`?presenter=<new key>`.
